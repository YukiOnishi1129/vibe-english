# Vibe English — デザインルール

> 英語を、勉強じゃなく毎日のノリに。

このアプリの見た目と手触りの決めごと。迷ったらここに従う。
新しい画面を足すときも、まずこの文書を読んでから CSS を書く。

参照元: [awesome-design-md-jp / timee](https://github.com/kzhrknt/awesome-design-md-jp)
のデザイン仕様を土台に、ダークモード対応と学習アプリ向けの役割定義を加えたもの。

---

## 1. 世界観

- **軽い**。毎日3分、サッと開いてサッと閉じる
- **ゲーム的だが子どもっぽくない**。押せる手応え、進捗の可視化
- **勉強アプリに見せない**。表や罫線を並べた「業務画面」にしない

---

## 2. 色の役割

色は装飾ではなく**意味を持つ**。役割から外れた使い方をしない。

| 色 | トークン | 意味 | 使う場所 |
|---|---|---|---|
| イエロー | `--yellow` | **達成・ブランド** | ヒーロー帯、完了ノード、進捗バー、ストリーク |
| ブルー | `--blue` | **次の行動** | 主CTA、現在地ノード、リンク |
| グリーン | `--green` | **正解・できた** | 「合ってた」「言えた」、正解表示 |
| オレンジ | `--orange` | **復習・つまずき** | 「間違えた」、復習バッジ、ブックマーク |
| レッド | `--red` | エラー | フォームの検証エラーのみ |

### 面積のルール（重要）

**イエローはベタ塗りの面を作らない。** 帯・バッジ・小さな面に限る。

```
○ 上部のヒーロー帯（横幅いっぱい、高さは控えめ）
○ 完了を示す円形ノード
○ 進捗バーの塗り
× カード全面をイエローで塗る
× 画面の半分以上がイエロー
```

イエローとブルーは彩度が高く、大面積で隣接させると目が痛くなる。
**イエローの面の中にブルーのボタンを置かない**（帯とパネルを分ける）。

### ダークモード

すべての色は CSS 変数で定義し、`prefers-color-scheme: dark` で差し替える。
**16進数を直接書かない。** 例外は、イエロー面の上に載る文字色（常に暗い文字）のみ。

---

## 3. かたち

| 要素 | 角丸 | 備考 |
|---|---|---|
| ボタン・タグ・ナビ項目 | `--radius-pill`（9999px） | 完全なピル型 |
| カード・パネル | `--radius-card`（1rem） | |
| 入力欄 | 0.9rem | |
| ノード（円） | 50% | |

枠線は **2px** を基本とする。1pxは細すぎて弱い。

---

## 4. 立体感

「押せる」ことを影で伝える。**ぼかした影は使わない**（`blur` なしのオフセット影）。

```css
/* 押せるもの */
box-shadow: 0 4px 0 <濃い同系色>;

/* 押した瞬間 */
transform: translateY(4px);
box-shadow: none;
```

影の色は要素の色の**暗い版**（`--blue-deep` など）。黒は使わない。

---

## 5. 文字

| 用途 | フォント | ウェイト |
|---|---|---|
| 見出し・フレーズ・ボタン・数値 | `--font-display`（M PLUS Rounded 1c） | 700〜800 |
| 本文・説明・日本語の解説 | Noto Sans JP | 400 |

丸ゴシックは同じウェイトでも細く見えるため、**大きい見出しは800**にする。

英語のフレーズは常に `--font-display`。日本語の長い説明文は Noto Sans JP。

---

## 6. 余白

- 画面の左右パディング: 最低 `1.25rem`
- カード内: `1.2rem` 以上
- 要素間: `0.5rem` / `1rem` / `1.5rem` を基本とし、中途半端な値を作らない

**詰めない。** 情報密度を上げると業務画面に見える。

---

## 7. 動き

| 場面 | 時間 | イージング |
|---|---|---|
| 押し込み | 0.08s | ease |
| カードの出入り | 0.18〜0.22s | ease |
| 色・不透明度 | 0.16s | ease |

`prefers-reduced-motion: reduce` では**すべてのアニメーションを止める**。
ループするアニメーション（現在地ノードの揺れなど）は特に必ず止める。

---

## 8. やらないこと

- **Duolingo の記号を真似ない**: 蛇行するパス、★の円ノードの多用、キャラクター
- **情報を詰め込まない**: 1画面1目的。一覧表を作らない
- **グラデーション**: 使わない（マーカー表現を除く）
- **ぼかした影**: 使わない
- **絵文字をアイコン代わりに使わない**: 中心がずれる。SVGを使う
  （装飾としての絵文字は可: 🔥 ストリーク、🎉 完了）

---

## 9. アクセシビリティ

- フォーカスリングは `:focus-visible` で統一（`--accent` の3px）
- イエロー面の上の文字は必ず暗い色（`#212121` 系）
- 色だけで状態を伝えない。アイコンや文言を添える
- 装飾目的の要素には `aria-hidden="true"`

---

## 10. ファイル構成

**1ファイル1コンポーネント。** ESLint (`local/one-component-per-file`) が強制します。

```
components/
  TodayView/              # Container / Presenter に分かれるもの
    index.ts              # Container だけを公開
    TodayViewContainer.tsx
    TodayViewPresenter.tsx
  NodeIcon/               # 単独コンポーネントも同じ形
    index.ts
    NodeIcon.tsx
```

- **Container**: hooks を呼び、値を Presenter に渡す。JSX は書かない
- **Presenter**: props を受けて描画するだけ。fetch・useQuery 禁止
- 補助コンポーネントも**独立したディレクトリ**に置く。同じファイルに同居させない

### 純粋関数は utils へ

コンポーネントや hooks のファイルに、描画・状態と無関係な関数を置かない。

```
features/chunks/
  utils/
    answer.ts     # 採点ロジック
    shuffle.ts    # 並び替え
```

utils はテストしやすく、`tests/` から直接 import できます。
